自部署有适用场景，但很多人的场景其实不满足。

## 我曾经以为掌握基础设施才算掌握 AI

我曾经认为，掌握模型部署、推理优化、算子调优，才是真正掌握 AI 基础设施。

于是我开始折腾：自己搭 vLLM，研究量化，研究路由，研究 Agent 框架，研究缓存策略，研究部署方案。

我以为我是在获得控制权。

后来发现，我是在进入一个新的行业。

## 真正的成本不是 GPU，而是隐藏工程成本

很多人对自部署的想象是这样的：

买几张卡 → 跑模型 → 收钱。

但实际链路是这样的：

硬件 → 驱动 → CUDA 环境 → 模型量化 → 推理框架 → KV Cache 优化 → 调度系统 → 路由 → Agent 框架 → 安全策略 → 监控 → 业务集成 → 用户增长。

你不是买了一台服务器。你是在养一个小型 AI 基础设施团队。

每一层都有自己的坑。驱动版本和 CUDA 版本对不上，量化精度掉了两个点，KV Cache 在高并发下 OOM，调度策略在多租户场景下互相抢占——这些问题不会因为你的卡够多就消失。它们只会因为你没有专职 infra 工程师而反复出现。

GPU 是明码标价的。但这些隐藏的工程成本，没人给你报价。

## AI 硬件最大的风险：算力成本下降

AI 硬件最大的风险不是不能用，而是单位算力成本快速下降，导致资产回报周期缩短。

这里讨论的是经济价值，不是物理寿命。卡还能跑，但它已经不划算了。

举个例子：今年你买一张卡，推理成本大约 1 元/百万 token。两年后，新一代卡的推理成本可能只有 0.3 元/百万 token。

不是不能跑。只是你的竞争力下降了。

你花大价钱建起来的推理集群，在成本曲线上被新硬件不断碾压。这不是工程问题，是经济学问题。而 API 调用天然把这个风险转嫁给了服务商——他们去扛硬件迭代的成本，你只为实际消耗的 token 付费。

## 什么情况下应该自部署？

不是所有场景都适合 API。自部署有它明确的适用条件，关键是对号入座。

### 隐私需求

自部署。没有讨论空间。

数据不能出去，合规有硬性要求，必须内网部署。这种情况下 API 根本不是成本问题，而是可行性问题。你连选择的余地都没有。

### 高参数 + 大规模

比如每天产生数亿甚至数十亿 token 的调用量。

可以考虑自建。因为在这个量级下，token 成本的优化空间可能覆盖掉工程维护成本。

但注意，关键不是"调用量大"。而是节省的钱是否超过你养一个 infra 团队的成本。如果优化 1% 的推理成本意味着每年省下几百万，那值得自建；如果只省下几万块，那不如把精力放在业务上。

### 高参数 + 中等规模

这是我认为最尴尬的区间。

而且现实中大量创业公司就在这里：想用大模型，不想太贵，规模又没有大到养得起基础设施团队。

自己部署，养不起优化团队，推理成本降不下来。调 API，又觉得每月账单肉疼。

两头不靠。这个区间的团队，我的建议是先算清楚：你的工程师时间值多少钱？如果折腾部署的时间本可以用来做产品迭代，那 API 大概率是更优解。

### 小模型 + 大规模

小模型、大规模，是最容易出现自部署经济性的场景。

但这里有一个反直觉的点：小模型并不一定天然便宜。商业推理成本不仅取决于参数量，还取决于部署规模、优化程度和供应链。

比如一个 100 亿参数的模型，如果没有人集中部署和优化，它的单位推理成本可能比热门大模型还高。市场上偶尔会出现价格倒挂：一些小模型由于缺乏规模化部署和深度优化，单位成本并不低于大型模型；同时新一代模型由于架构改进和基础设施优化，价格反而在下降。

所以"用小模型就能省钱"这个假设，需要先验证。

## 为什么大厂选择自部署？

大厂拥有大规模请求、数据闭环、算法团队、infra 团队、硬件采购议价能力。

他们不是"自部署先进"。是他们的规模让自部署变成了经济选择。

对一家每天产生数十亿 token 请求的公司来说，优化 1% 的推理成本可能意味着每年数千万的收益。但对于个人开发者来说，同样的 1% 可能只是省下一杯咖啡的钱。

规模决定了自部署的 ROI 曲线。没有那个规模，硬套那个方案，账算不过来。

## 为什么个人项目现在更适合 API？

把前面的分析收拢一下：

对于大多数没有特殊约束的个人开发者和小团队，当前阶段自建大模型推理基础设施的收益，很容易低于直接调用成熟 API。

自部署不是错。但它是一种需要满足特定条件的工程选择：要么有隐私硬约束，要么有足够大的调用量来摊薄工程成本，要么有专职团队持续优化。

如果这三条一条都不满足，那自部署带来的不是控制权，而是负担。

当然，如果目标是学习 AI infra，自部署非常值得——你会真正理解推理链路里每一层在干什么。但如果目标是快速做产品、验证想法，API 是阻力最小的路径。

先跑通业务，再考虑基础设施。顺序反了，容易陷在工程细节里忘了自己要做什么。

## 延伸：大模型价格背后的优化逻辑

API 价格为什么能持续下降？背后是多层优化的叠加。

模型层面：MoE 架构让激活参数量远小于总参数量，推理时实际计算量大幅减少；量化技术（INT8、INT4）在不显著损失精度的前提下压缩显存占用和计算开销；蒸馏和剪枝让更小的模型逼近大模型的效果。

系统层面：KV Cache 优化（PagedAttention、Prefix Caching）提高了显存利用率和并发吞吐；Continuous Batching 让 GPU 不再空等；投机采样（Speculative Decoding）用小模型加速大模型的生成过程。

硬件层面：新一代芯片的算力和显存带宽持续提升，单位 token 的硬件成本在下降；推理专用芯片和定制 ASIC 进一步压低成本。

这些优化的红利，API 服务商在持续吃。你调用 API，本质上是在搭这些优化的便车——而不需要自己维护任何一层。

这也是为什么对大多数个人项目来说，现阶段调 API 不只是"省事"，而是在经济上确实更优的选择。
